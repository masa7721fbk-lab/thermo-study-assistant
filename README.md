# 熱力学ノート

これは、現在流体力学や熱力学の授業をより効率的に進めるために作りました。熱力学の問題を解くとき、「答えは分かっても、授業のどこを復習すればよいか分からない」という不便から作った学習アプリです。質問・問題写真・途中式を送り、解説を読んで、そのまま追加質問できます。関連する教材ページも一緒に案内します。（教科書は工業熱力学）
**[公開デモを開く](https://thermo-study-demo.mellowcomet39.chatgpt.site/)**

## 使い方

1. 「WとJの違いは？」などを入力するか、問題写真を選びます。
2. 必要なら、自分の考えや途中式を添えて「質問する」を押します。
3. 考え方・計算と答えを読み、分からない点は回答の下から追加質問します。
4. 「参照した教材」「復習するページ」を開き、手元の教材で確認します。

デモは回数制限付きです。教材に根拠がない部分は一般知識で説明し、利用者が選んだときだけ外部検索を追加します。登録してある教材索引は1冊分で、他の利用者の教科書にはページ番号が対応しません。

## 実装したもの

- 文章と最大2枚の画像（問題・途中式）の入力　画像は10mbまでです
- Gemini APIによる解説、途中式の確認、計算と答えの生成
- 過去の回答を残す追加質問。元の写真と最初の質問・直近2往復を送信
- 説明文と数式を分けた表示（Unicodeの数式。LaTeX組版ではありません）
- 登録済み教材IDに基づく参照ページと復習候補（細かい行や問題番号までは対応できませんでした）
- 利用者が選択した場合だけGoogle Searchによる追加確認と出典表示
- 公開Webアプリとしての配信、入力検証、タイムアウト、簡易回数制限

## 構成

~~~text
ブラウザ（HTML / CSS / JavaScript）
    ├─ 教材の語句検索 → materials.json（ブラウザ内）
    └─ POST /api/ask → Worker → Gemini API
                          ├─ 入力・画像の検証
                          ├─ 教材の要約と会話履歴を送信
                          └─ JSONの形式・教材IDを検証 → 画面に表示
~~~

公開版はSites経由でCloudflare Workersに配信しています。AWS / GCPへのデプロイを実施したプロジェクトではありません。APIキーはサーバーのシークレットで管理し、ブラウザには返しません。

教材は手元の資料を確認して作った小規模なJSON索引です。通常回答では全索引をモデルに渡します。**PDF全文の自動検索やベクトル検索を使ったRAGは未実装です。** 教材IDの検証は架空のIDを防ぎますが、回答内容と出典の意味的な一致を保証するものではありません。

## ローカルで動かす

Node.js 22以上を使います。外部npm依存はありません。

~~~sh
git clone https://github.com/masa7721fbk-lab/thermo-study-assistant.git
cd thermo-study-assistant
~~~

.env.example を .env にコピーし、自分の環境の値で設定します。

| 変数 | 内容 |
| --- | --- |
| GEMINI_API_KEY | 自分のGemini APIキー |
| SESSION_SECRET | 外部検索の許可トークンに使うランダムな秘密値 |
| GEMINI_MODEL | 利用できるGeminiモデルID |
| PORT | ローカルのポート番号。既定値8787 |

SESSION_SECRETの作成例（出力を.envへ記入）:

~~~sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npm run dev
~~~

ブラウザで http://127.0.0.1:8787/ を開きます。APIキー未設定でも画面と教材検索は確認できます。API送信には自分のGemini APIの利用枠が必要です。HTMLファイルを直接開く方法ではAPIは動きません。

~~~sh
npm test
npm run validate
~~~

テストはGemini APIをモックし、実際のAPI使用量を消費しません。

## ファイル

| 場所 | 役割 |
| --- | --- |
| worker/page.html | 入力欄と画面構造 |
| worker/style.css | 色、余白、レイアウト |
| worker/app.js | 画像、会話、回答・出典表示 |
| worker/api.js | API中継、プロンプト、検証、利用制限 |
| worker/materials.json | 教材の見出し、要約、ページ索引 |
| scripts/build.mjs | HTML・CSS・JSをWorkerにまとめる |
| scripts/dev.mjs | ローカル開発用HTTPサーバー |

.openai/hosting.json は配信用の汎用設定です。このリポジトリに公開サイト固有のIDや秘密値は含めません。公開には自分の配信環境とシークレットの設定が別途必要です。

## 検証と制約

モックテストでは、PDF非公開、秘密値非返却、通常回答と外部検索、別Originからの拒否、会話履歴の送信・上限・トークンとの結び付けを確認しています。数学的な正答率を測る評価セットはまだありません。

- 写真の読み取りやAIの計算が間違う場合があります、テストでは計算ミスもありました、条件と単位を確認してください。質問で指摘すると正しいあたいになることもあります。
- 画像・文章は送信時にGoogleのAPIで処理されます。アプリ独自の会話保存DBはなく、再読み込みで会話は消えます。API提供元のデータ取り扱いは別途適用されます。
- 著作権のある教材PDF・問題写真はリポジトリや配信物に含めません。
- 利用制限はWorkerのメモリ内でIPごとに管理しています。永続的・全体的な課金上限や認証の代替ではありません。
- 正答率の記録、弱点の自動分析、教材アップロード、個別設問の精密な類題検索は未実装です。

## 制作について

自分の熱力学学習で必要だった機能を考え、問題を実際に試しながら、追質問や数式表示、教材で裏付けられないときの扱いを改善しています。実装・デバッグ・公開準備には生成AIの支援を使いました。そもそもgithubは最近始めたのでSSHキーなどの初期環境準備に時間がかかりました。実装での問題は壁打ち相手としてAIを利用することで、学びを得られました。企画と動作確認を行いながら、コードと仕組みを学んでいる個人開発です。

次は、手元の演習で解答・単位・引用ページを評価し、その結果をもとに教材追加と検索を改善する予定です。
